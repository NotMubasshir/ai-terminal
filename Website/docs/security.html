SECURITY

The model is not the security boundary.

AI Terminal assumes model output, repository content and command output can be hostile.

Enforcement order

Structured tool call
  ↓
Tool lookup
  ↓
Argument validation
  ↓
Path / command validation
  ↓
Deterministic risk classification
  ↓
Permission policy
  ↓
Real execution
  ↓
Bounded result + audit log

Permission modes

  • always_ask — ask for every non-safe operation.
  • dangerous_only — ask for high-risk operations.
  • safe_auto — automatically allow safe/low operations.
  • session — session-scoped approvals after policy evaluation.
  • always_deny — deny every non-safe operation.

Filesystem boundary

AI-controlled paths are constrained to the configured workspace. Traversal, absolute escapes and existing Windows reparse-point components are rejected. Checks happen immediately before execution.

Prompt injection

README files, comments, source code, Git messages and tool output are data. Text such as “ignore previous instructions” does not gain authority because it came from a repository or command result.

Secrets

The Gemini API key is read from GEMINI_API_KEY. It is not written into application configuration. Environment inspection is allowlisted, and audit logging redacts common secret-bearing fields.

Process containment

Long-running Windows child processes are time-bounded and can be attached to Job Objects so child processes do not remain uncontrolled after the parent operation ends.

Residual risk

AI Terminal is not a VM or operating-system sandbox. An approved command still has the privileges of the Windows account running the application. The product's security model is designed to reduce model-driven and accidental abuse while keeping consequential actions under user policy.

For a full threat inventory: see docs/THREAT_MODEL.md in the source repository.
