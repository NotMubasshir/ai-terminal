Windows APIs

Agent states

The runtime uses explicit states including IDLE, THINKING, PLANNING, AWAITING_PERMISSION, EXECUTING, OBSERVING, VERIFYING, RECOVERING, COMPLETED, FAILED and CANCELLED.

Provider boundary

AIProvider isolates provider-specific HTTP and response handling from the agent runtime. Gemini is the production provider; the mock provider enables deterministic tests without a network request or API key.

Windows process model

Process execution uses Windows APIs, bounded output, timeouts and cancellation. Where available, Job Objects provide process-tree containment.

Why this structure?

The architecture is deliberately boring in the best sense: each component has a narrow responsibility, security decisions are centralized, and the runtime can be tested without a live model.
